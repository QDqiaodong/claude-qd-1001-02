# 造纸厂 · 制浆抄纸与纸卷切裁管理

一套面向造纸厂的车间级业务系统：从制浆工段的浆池储存，到抄纸工段的纸机与母卷，
再到切纸工段的订单排产与母卷校验，最后到成品库的成品件出入库。

## 启动

```bash
./start.sh          # 镜像已存在时直接起
./start.sh --build  # 改过代码后必须加 --build，否则跑的还是旧镜像
./stop.sh           # 停止
```

启动后：

- 前端 http://127.0.0.1:8301
- 后端 http://127.0.0.1:8401
- MySQL 3601 / Redis 6601

## 四个业务模块

### 1. 制浆工段 · 浆池
- 浆池台账（编号 / 浆种 / 容量 / 存量 / 状态）
- 补浆与抽浆：只有「在用」池可操作，单次补浆不超过 50 m³，补浆后不得超过容量
- 状态流转：在用 → 检修 → 在用；停用池只能先转检修

### 2. 抄纸工段 · 纸机与纸卷
- 纸机台账（设计幅宽 / 设计车速 / 状态）
- 纸机状态与母卷产出准入联动：运行/停机可带检修原因、开始/预计结束时间和经办人发起检修
- 提交检修前在同一事务和纸机行锁内检查「待检」未完成产出登记；有待检母卷时明确列出卷号并阻止检修
- 检修中禁止新建母卷、禁止把待检母卷判为「可用」；阻止原因与操作人持久化，刷新后仍在纸机导轨显示
- 检修完成只能回到「停机」，由经办人确认后才恢复「运行」；并发检修/恢复只放行一方，另一方看到当前状态和原因
- 当前检修单、检修历史、母卷归属与切裁台账都保留在纸机导轨上，检修状态变化不会删除既有母卷
- 纸卷（母卷）产出：幅宽不得超过所属纸机设计幅宽
- 等级按「实测定量 vs 目标定量」偏差自动判定：≤2 一等，≤5 二等，超过判等外
- 状态流转：待检 → 可用 / 报废；可用 → 已切完 / 报废

### 3. 切纸工段 · 切纸订单
- 订单按「定量 + 幅宽 + 重量」下达
- 母卷校验：幅宽必须 ≥ 目标幅宽、定量偏差不得超过 3、母卷必须是「可用」
- 状态推进：待排产 → 切裁中 → 已完成（不可跳级），可旁路取消

### 3.1 切纸工段 · 切裁领料闭环
- 只有「切裁中」订单能从「可用」且规格匹配（幅宽 ≥ 目标、定量偏差 ≤ 3）的母卷登记领料
- 领料记录保存订单、母卷、本次长度/重量、操作时间、操作人，并定格扣减后的母卷余量
- 校验与扣减在同一事务内完成：订单状态、母卷状态、规格匹配、长度重量为正且不超过真实余量，
  任一条件失效只留失败原因（不写记录、不动余量）；成功则同动作扣减余长余重，
  余长低于 200m 阈值母卷同步转「已切完」，已成功的记录不随状态变化消失
- 幂等与并发：请求带 requestToken，重复点击/重试只返回原结果；
  母卷行 `SELECT ... FOR UPDATE`，两名操作员同时领同一母卷时只有余量实际可满足的一方成功
- 双向追溯：订单详情与母卷导轨都能查领料账本；失败原因持久化，刷新/重开页面仍可见

### 4. 成品库 · 成品件与出入库
- 入库件规格必须与订单目标一致（定量允许 3 的偏差，幅宽必须相等）
- 入库重量不得超过订单欠量，入库后回写订单已入库量
- 出库单向：已入库 → 已出库

- 后端：Spring Boot 3.3 / Java 17 / Hibernate 6
- 前端：Vue 3 / Element Plus / Vite

### 后端路线：`@LazyCollection(EXTRA)`

一台纸机常年累积上千个纸卷。纸机的纸卷集合用 Hibernate 的
`@LazyCollection(LazyCollectionOption.EXTRA)` 声明：

- 只问「有多少卷」（`size()`）时走 `select count(*)`，不装载集合；
- 只问「某卷是不是这台机的」（`contains()`）时走 `exists` 查询；
- 只有真正遍历集合内容时才发出完整查询。

见 `PaperMachine.rolls` 与 `PaperMachineService.summary()`。

## 界面

- 主色：墨绿 `#004d40`
- 导航：顶部 Mega 下拉菜单（悬停展开宽面板，三列快捷入口）
- 各页操作范式：
  1. 浆池——容量计量条 + 补浆滑杆（超限标红并锁按钮）
  2. 纸机与母卷——纸机导轨 + 纸卷长度条
  3. 切纸订单——完成率进度环 + 母卷匹配清单打勾
  4. 成品库——库区货位网格 + 勾选批量出库（底部浮条）
